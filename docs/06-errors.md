# 06 · 错误处理

## 1. 统一错误体

所有由 `HttpException` 产生的响应都是这个形状：

```json
{ "statusCode": 403, "message": "无权下载未通过审核的图片", "error": "Forbidden" }
```

参数校验失败时 `message` 是**数组**（`ValidationPipe` 的默认行为，顺序与 DTO 字段声明一致）：

```json
{
  "statusCode": 400,
  "message": ["页码必须大于等于 1", "每页数量不能超过 100"],
  "error": "Bad Request"
}
```

客户端解析时必须同时兼容 `string` 与 `string[]`。

## 2. 状态码语义

| 码 | 何时出现 | 客户端应做 |
|---|---|---|
| `400` | 参数校验失败、业务前置条件不满足（拒绝未给原因、审核态非法、标签不存在、密码错误） | 原样展示 `message`，不要重试 |
| `401` | 没带 token、token 无效/过期 | 清 token → 跳登录；`/auth/refresh` 换新 token |
| `403` | 角色不足、不是本人、禁止自审、未过审图片 | 提示无权限；**不要**重试 |
| `404` | 资源不存在（含「私有图集对无权者伪装成不存在」） | 提示不存在 |
| `409` | 状态冲突（重复审核、并发审核、用户名/邮箱被占用） | 提示刷新后重试 |
| `429` | 登录失败次数超限、当日上传数超限 | 读 `retryAfterMs` 后倒计时，不要立即重试 |
| `500` | 文件缺失/被篡改、解密失败、数据库异常 | 提示联系管理员；可重试一次 |
| `503` | 图库处于锁定态（进程解不开数据密钥） | 提示管理员解锁；页面展示只读态，不要重试

角色不足时 `RoleGuard` 的固定文案是 `` `权限不足：需要 ${minRole} 及以上角色` ``（如 `权限不足：需要 MODERATOR 及以上角色`），所有 MODERATOR+/ADMIN+ 接口共用这一句。

## 3. 各端点错误速查

文案均从源码逐字摘出，可直接用于前端的错误映射表。

### 3.1 认证

| 端点 | 码 | message |
|---|---|---|
| `POST /auth/login` | 400 | `用户名或密码错误` |
| | 429 | `登录失败次数过多，请 N 秒后再试`（body 额外带 `retryAfterMs`） |
| `POST /auth/refresh` | 401 | `无效的刷新令牌` / `刷新令牌已过期` |
| `GET /auth/public-key` | — | 不会失败 |

`429` 的完整 body：

```json
{
  "statusCode": 429,
  "message": "登录失败次数过多，请 892 秒后再试",
  "error": "Too Many Requests",
  "retryAfterMs": 891540
}
```

### 3.2 用户

| 端点 | 码 | message |
|---|---|---|
| `POST /users` | 400 | `用户名至少3个字符` / `密码至少6个字符` / `邮箱格式不正确` |
| | 409 | `用户名或邮箱已被注册` |
| `GET /users/:id` | 403 | `无权查看其他用户的详细信息` |
| | 404 | `用户 ID <id> 不存在` |
| `PATCH /users/:id` | 403 | `无权修改其他用户的信息` / `用户名仅限本人修改` / `超级管理员用户名不可修改` |
| | 404 | `用户 ID <id> 不存在` |
| | 409 | `用户名已被占用` / `邮箱已被其他用户使用`（软删除用户仍占用） |
| `DELETE /users/:id` | 403 | `超级管理员账号不可删除` / `无权删除该用户` |
| | 404 | `用户 ID <id> 不存在` |
| `PATCH /users/:id/role` | 403 | `超级管理员账号的角色不可被修改` / `不能修改自己的角色` / `无权修改该用户的角色` / `无权将该用户设置为目标角色` |
| | 400 | `角色必须是有效的枚举值` |
| `PATCH /users/me/password` | 400 | `原密码错误` / `新密码至少需要6个字符` / `密码解密失败，请使用正确的公钥加密` |

### 3.6 图库密钥

| 端点 | 码 | message |
|---|---|---|
| `POST /library/unlock` | 400 | `图库密码错误` |
| | 401 / 403 | 未登录 / 非 ADMIN+（`权限不足：需要 ADMIN 及以上角色`） |
| `POST /library/password` | 400 | `原图库密码不正确` / `新密码不能与原密码相同` |
| | 401 / 403 | 同上 |

加解密失败时的文案（出现在图片与图库接口里，都是 5xx）：

| 码 | message |
|---|---|
| 503 | `图库处于锁定状态，请管理员先调用 POST /api/library/unlock 解锁` |
| 503 | `缺少数据密钥 vN，无法解密图片。请管理员用当前图库密码重新解锁，或重新设置图库密码以触发重加密` |
| 500 | `图片解密失败：文件已损坏，或密钥与图库密码不匹配` |

## 4. 重试建议

| 场景 | 建议 |
|---|---|
| 网络错误 / 5xx | 指数退避重试 2 次 |
| `401` | 先尝试 `/auth/refresh`，失败再跳登录；不要立即重试原请求 |
| `409` | 重新拉一次详情，把最新状态展示给用户，由用户决定 |
| `429` | 按 `retryAfterMs` 等待，期间不要发登录请求 |
| `400` / `403` / `404` | 不重试 |

## 5. 日志里的对应关系

- 5xx 会把异常堆栈写进 `logs/error/`。
- 所有写操作（非 GET/HEAD/OPTIONS）都会在 `audit_logs` 留一条记录，`success = statusCode < 400`，失败请求也记，可用 `GET /api/audit-logs?action=…` 回查。
